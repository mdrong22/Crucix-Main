Crucix · Trading Brain

Project RedLine
System Guide

The autonomous-research, human-approved trading layer of Crucix. What it is, the ideas behind it, how it works end to end, and an honest accounting of where it's strong and where it isn't. Read top to bottom; use the file map as reference.

01High concept

RedLine turns a firehose of market + world data into one well-reasoned trade suggestion at a time, and (by default) asks you before it acts.

Most retail trading bots are reactive and autonomous: a rule fires, an order goes out. RedLine is the opposite shape on purpose:

  • One analyst, not a rule engine. A single LLM agent ("Claude") reviews the whole situation each cycle the way a human analyst would — weighing a thesis, a counter-thesis, the portfolio, and its own past performance — and emits at most one proposal.
  • Recommends, doesn't execute. Proposals are Accept/Deny cards. Nothing hits the brokerage until you approve (unless you flip on Auto mode). The one exception is capital protection: hard stop-losses sell without asking.
  • Breadth most retail systems don't have. It fuses ~39 live sources — macro/economic, live prices, congressional trades, SEC filings, policy/executive actions, semiconductor lead indicators, and geopolitical OSINT — into the analyst's view.
  • It learns. Every resolved trade feeds a track record and a confidence-calibration score back into the agent's next decision, so it adjusts toward what has actually worked.

The guiding value, adapted from risk-first trading desks: "survives" beats "looks profitable." Discipline (stop-losses, a circuit breaker, position sizing, approval gating) is never waived; aggression is a dial on top of it.

02Design principles

  1. Human-in-the-loop by default. Approval gating is the safety model. Auto mode is opt-in.
  2. Deterministic risk, independent of the model. The stop-loss watcher and the account circuit breaker are plain code with hard thresholds. The LLM cannot argue its way past them.
  3. Quality over quantity. Most cycles are NO_ACTION. A daily new-buy cap discourages overtrading.
  4. Every call is explainable. Each proposal carries reasoning, a bearCase, cited sources, and a confidence score. Reports are generated for the record.
  5. Memory and learning. A per-stock "stance book" gives cross-cycle consistency; a track record + calibration close the feedback loop.
  6. Token-frugal. The sweep is distilled to a compact (~700–900 token) digest; the default agent runs on a Claude subscription via the CLI rather than per-token API billing.

03The decision pipeline (end to end)

Sources  →  Synthesize  →  Agent context  →  Claude decides  →  Accept → Execute  →  Feedback ↻
(~39 feeds)  (clean+delta   (+ portfolio,     (think → bear      (guards →          (resolve P&L →
             +ideas/theses)  stances, record,  case → ONE call)   place order)       recalibrate)
                             guardrails)              │
                                                      └──→ NO_ACTION (nothing trades)

The feedback arrow is the point: resolved outcomes re-enter the agent's context, so the loop tightens over time. The stance book also updates "sideways" every cycle — even on a NO_ACTION sweep the agent can revise its per-stock plan, so its memory changes far more often than it trades.

04Architecture, layer by layer

4.1 Data layer — the sweep

  • Entry: apis/briefing.mjs → fullBriefing() runs ~39 sources in parallel, each with a 30s timeout. Failures are isolated — one dead feed never stalls the sweep.
  • Sources span tiers: core OSINT/geopolitical (GDELT, OpenSky, FIRMS, ACLED…), economic/financial (FRED, Treasury, BLS, EIA, GSCPI), live market data (Yahoo quotes + movers), congressional trades + insiders (Bargo), policy/executive actions (Federal Register), SEC EDGAR (8-K/Form 4), semiconductor lead indicators (TrendForce), and news (Finnhub, NewsAPI). Many are keyless; see SOURCES.md.
  • Synthesis: dashboard/inject.mjs → synthesize() maps raw payloads into clean, predictable fields — the boundary where "40 different API shapes" becomes one schema.
  • Delta + memory: lib/delta compares this sweep to the last and flags what escalated or is new, gating expensive LLM work when nothing material changed.

4.2 Intelligence layer — shared market read

  • Ideas (lib/llm/ideas.mjs) — a market-wide brief of leverageable setups, throttled and delta-gated.
  • Theses (lib/llm/thesis.mjs) — forward-pacing megatrend → "unpriced rung" maps (a trend's bottleneck → the second-order stock that benefits). Cached across restarts.
  • The digest: compactSweepForLLM() distills everything the agent needs into a compact text block — the single biggest token lever.

4.3 The agent — one analyst, one call

  • Core: lib/llm/analyst.mjs → generateProposal(). One provider.complete() call to Claude (default via the claude CLI on a subscription; Gemini fallback). No tool-calling loop — the context is pre-assembled and the model returns one JSON object.
  • The system prompt encodes the method: THINK FIRST (write reasoning and the strongest bearCase before deciding — if the bear case wins → NO_ACTION); PRIORITY (urgent maintenance → best new buy → NO_ACTION); R/R floors, PDT handling, size-to-buying-power, "small size is fine".
  • Horizons double as risk bands: INTRADAY (~-2% stop), SWING (~-5%), LONG (~-12%), each with trailing behavior. A mandatory stopLoss is required on every new buy.
  • Strategy modes tune the bar for acting, never the risk floors: Conservative / Balanced / Aggressive / Scalper, plus regime-aware AUTO (high VIX → Conservative, calm + risk-on → Aggressive, heavy dislocation → Scalper).

4.4 Memory & learning

  • Stance book (lib/stances/store.mjs) — the agent's living per-stock plan: a stance (WATCH / ACCUMULATE / HOLD / TRIM / EXIT / AVOID), a thesis, an entry plan, an exit, a confidence, and an investment horizon. Persists across sweeps and is revised via stanceUpdates — consistency instead of deciding from scratch.
  • Track record (lib/llm/trackRecord.mjs) — resolved trades distilled into win rate, profit factor, by-horizon/by-signal performance, plus behavioral self-corrections ("your avg win is smaller than your avg loss — you're cutting winners short").
  • Confidence calibration (lib/llm/calibration.mjs) — buckets resolved trades by claimed confidence vs. realized win rate, plus a Brier score (0 = perfect, 0.25 = coin-flip). Tells the agent when it's over- or under-confident, and in which band.
  • Standing directives (lib/directives/store.mjs) — general user instructions the agent must follow, added via "Propose a Plan".

4.5 Risk layer — deterministic, model-independent

  • Hard stop-loss watcher (lib/alerts/stopLossWatcher.mjs) — runs on its own fast timer, bypasses Accept/Deny, auto-sells using each proposal's stop (or the per-horizon floor), trails to lock gains, and handles the intraday EOD lifecycle. The one place the system acts without you.
  • Account circuit breaker (lib/risk/circuitBreaker.mjs) — if the account is down more than maxDailyLossPct on the day or maxDrawdownPct from its peak, it halts new buys (maintenance/exits still allowed). It pauses new risk; it does not auto-flatten.
  • Mechanical guards on Accept — a live-quote sanity check (rejects implausible prices — a hallucination guard), the PDT day-trade circuit, a fractional→Day fix, and a no-size rejection before any order is sent.

4.6 Execution & proposal lifecycle

  • Store (lib/proposals/store.mjs) — each proposal persists with a status: PENDING → ACCEPTED | DENIED | EXPIRED | EXECUTED | FAILED. Expiry deletes the Telegram card so stale offers disappear.
  • Accept path (server.mjs → acceptProposal) — guards → snapTrade.PlaceOrder → logDecisions → generateTradeReport. In Auto mode a proposal self-accepts and the card is edited in place to the real outcome (✅ Executed / ❌ Failed).
  • Brokerage (lib/alerts/snaptrade.mjs) — SnapTrade; reads cached + throttled; a full exit uses ClosePosition (exact owned quantity, no dust).

4.7 Delivery & control

  • Dashboard (dashboard/public/redline.html) — portfolio header + value chart, positions, orders, the stance book (with clickable tags + horizon), the decision-cycle panel with a live calibration Brier readout, a ticker strip, a reports viewer, and a settings gear.
  • Telegram (lib/alerts/telegram.mjs) — Accept/Deny cards to a proposals channel; alerts to a news channel. Commands: /info /plan /propose /ask /stance /cooldowns /lift /portfolio (trades) and /status /sweep /brief /ask (news).
  • Propose a Plan / Ask — push an idea or directive (agent returns ACCEPT / PARTIAL / DENY), or ask read-only questions grounded in the live plan + sweep.

4.8 State (the runs/ directory)

Flat JSON stores, each a single source of truth: settings.json, stances.json, decisions.json (the trade ledger + resolved P&L), proposals.json, directives.json, breaker.json, theses.json, moratoriums.json, ma-state.json, latest.json.

05How it learns (the loop that matters)

  1. A proposal is accepted → logDecisions records it with the stated confidence.
  2. positionResolver later marks it resolved (win/loss/breakeven + P&L).
  3. On the next sweep, buildTrackRecord() and buildCalibration() read the resolved ledger and inject compact self-corrections into the agent's context.
  4. The agent adjusts: downweights losing horizons/signals, leans into winners, recalibrates its confidence numbers.

This is the single biggest lever on decision quality — it turns a reactive proposer into something that improves with its own history. It only activates after a minimum sample (TRACK_RECORD_MIN, CALIBRATION_MIN) so it doesn't over-fit two trades.

06Strengths

  • Safety-first by construction. Approval gating + a deterministic risk layer the model can't override — a genuinely different posture than autonomous rule bots.
  • Analyst-grade breadth. Macro + policy + congressional + SEC + semiconductor + OSINT in one view, with a top-down "megatrend → unpriced rung" funnel.
  • It explains itself. Reasoning, an explicit bear case, cited sources, and a confidence number on every call — plus generated reports.
  • It calibrates. Track record + Brier-scored confidence attacks the two classic failure modes (overconfidence, cutting winners short).
  • Consistency via memory. The stance book keeps a coherent plan per stock across cycles.
  • Cost-efficient. Token-frugal digest; default agent on a Claude subscription; most sources free-tier or keyless.
  • Tunable aggression without tunable risk. Strategy modes move the bar for acting while the stop-loss / R-R / circuit-breaker floors stay fixed.

07Weaknesses & limitations

  • Signal fragility on free tiers. Keyed sources go dark when a quota is exhausted; the agent isn't yet told which signals are dark.
  • Latency vs. autonomous bots. Approvals happen at sweep interval, and every exit except the hard stop is a proposal — a deliberate trade of speed for control.
  • Cold-start learning. Track record + calibration need a meaningful sample; learning is live-only (no backtest/paper harness yet).
  • LLM variance. Guards catch mechanically unsafe orders, not a plausible-looking bad idea — a user can still accept one.
  • Attribution is per-confidence, not yet per-source. The system doesn't yet measure which of the ~39 sources actually predict outcomes, so breadth can add noise.
  • Single-tenant, flat-file state. runs/*.json isn't concurrency-safe or namespaced per user; multitenancy is designed but not built.
  • Operational dependencies. The default agent needs the claude CLI logged in on the host; SnapTrade + Telegram must be configured; a few data points are cached/stale.
  • Stock/market-hours bound. It operates in market windows, not 24/7.

09Where it's headed

The near-term architectural goal is multitenancy: one shared data server runs the ~39-source sweep + the ideas/thesis LLM and writes synthesized intelligence to a database; many RedLine instances read from it and add per-user portfolio/stances/execution on top. Market/OSINT keys are global and set up once; only SnapTrade user credentials and Telegram chat IDs are per-tenant. The real work is making per-tenant state isolated and concurrency-safe.

Other natural extensions: per-source predictive scoring (prune breadth to what pays), a paper/backtest harness so learning isn't live-only, a data-health line in the agent context, and a news-first catalyst detector (catch a guidance/earnings surprise before the big price move).

10Discovery & per-position intelligence

Two capabilities sit on top of the base pipeline: finding new names, and watching the ones you already hold with company-level depth. Both run inside the sweep and feed the agent digest.

Per-name intelligence — each sweep, every name you hold, have a stance on, or that ranks as a discovery candidate is pulled individually, not just as a macro headline:

Digest lineWhat it isSource
POSITION_NEWScompany-specific headlines (court rulings, guidance, downgrades…)Finnhub /company-news
INSIDER_SELLSexecs/directors reducing a holding (bearish)Finnhub insider txns
INSTITUTIONAL_SELLS13F funds cutting stakes (quarterly, cached)Finnhub institutional-ownership
POSITION_TECHNICALSprice vs 50/200-day MA, RSI, RS vs SPY, trendAlpaca bars
MA_CROSSa FRESH cross this sweep (price ±MA, death/golden), hysteresis-debouncedmaCrossStore.mjs

Discovery board (MARKET_SETUPS) — lib/discovery/discover.mjs harvests every ticker the sweep's signals already name (congress/insider buys, upgrades, option sweeps, 8-Ks, movers scaled by magnitude, thesis targets, prior ideas), scores each by catalyst strength, enriches the top ones with the news + chart above, and ranks a shortlist. A min-conviction floor (DISCOVERY_MIN_SCORE) drops single-signal noise; counter-trend (<200-MA) and insider/13F-selling names are down-weighted. The agent's NEW_BUY step hunts here first.

Post-stop moratorium (lib/risk/moratorium.mjs) — a hard-stop puts the ticker on a re-entry cooldown and logs the failed thesis, so the system doesn't immediately re-buy a name that just stopped it out, and the failure informs later decisions (/cooldowns, /lift).

Position lifecycle controls

  • Investment-type retype — the agent (or you, via /propose) can promote a held position INTRADAY→SWING→LONG when a winner has more room; the live stop floor + EOD behavior change to match.
  • Intraday EOD lifecycle — a late-session INTRADAY entry is blocked (INTRADAY_ENTRY_CUTOFF, no same-day runway); at the close an INTRADAY winner is profit-locked and a loser holds overnight.
  • Anti-whipsaw — MA-cross hysteresis + an anti-churn hold guard (a just-entered loser isn't soft-exited on a reversed signal; winners still scalp fast; the hard stop always covers the downside).
  • Direct stance control — set any tag now (/stance <TICKER> <HOLD|WATCH|EXIT|…> or the dashboard ✎), independent of the agent.
  • Every exit writes a report — agent sells, hard stops, trailing/EOD profit-locks — each with the realized result (entry → exit, up/down, WIN/LOSS verdict).

11Worked example — how a new name is discovered (ORCL +12%)

A name you don't hold enters the system only through the movers screener — then travels to the agent:

  1. Front door — movers. apis/sources/movers.mjs (Yahoo gainers screener) ranks ORCL at +12% → synthesized.movers.gainers. (Digest: MARKET_GAINERS: ORCL +12%.)
  2. Scored. harvestAndScore() scores the gainer by magnitude — ≥10% → 3 (a small wiggle would be 1 and filtered as noise; this is how a real catalyst mover clears the board but RIG-style churn doesn't).
  3. Monitored. ORCL joins the enrichment set both as a top candidate and as a big mover (≥6%).
  4. Enriched — the "why". POSITION_NEWS pulls "Oracle surges on FY2029 $30B free-cash-flow guidance" (the catalyst); POSITION_TECHNICALS shows it above both MAs, strong RS.
  5. Board. annotateBoard() → score 3 + setup + news ≈ 4 ≥ DISCOVERY_MIN_SCORE → it lands on MARKET_SETUPS with its headline attached.
  6. Agent sees it. buildAnalystContext leads the NEW_BUY hunt from MARKET_SETUPS; ORCL is right in front of the agent, with the guidance catalyst and chart, to judge re-rating vs. chase.
  7. If it buys → the normal gates (regular-hours · intraday cutoff · moratorium · size) → execute → stance HOLD + horizon → hard stop → trade report.

The boundary: this is price-move triggered — ORCL's news is pulled because the move was big enough to rank in movers. If it had re-rated on the same news with only a +3% candle (and you didn't hold it), it would still be filtered. A news-first "guidance/earnings-surprise" signal is the next upgrade to catch catalysts before the big move.
