Crucix · Trading Brain

Project RedLine
System Guide

The autonomous-research, human-approved trading layer of Crucix. What it is, the ideas behind it, how it works end to end, the agent and position lifecycles, and an honest accounting of where it's strong and where it isn't.

01High concept

RedLine turns a firehose of market + world data into one well-reasoned trade suggestion at a time, and (by default) asks you before it acts.

Most retail trading bots are reactive and autonomous: a rule fires, an order goes out. RedLine is the opposite shape on purpose:

  • One analyst, not a rule engine. A single LLM agent reviews the whole situation each cycle — thesis, counter-thesis, portfolio, its own past performance — and emits at most one proposal.
  • Recommends, doesn't execute. Proposals are Accept/Deny cards; nothing hits the brokerage until you approve (unless you flip on Auto). The one exception is capital protection: hard stop-losses sell without asking.
  • Breadth most retail systems don't have. ~39 live sources — macro, prices, congressional trades, SEC filings, policy actions, semiconductor lead indicators, OSINT.
  • It learns. Every resolved trade feeds a track record + confidence calibration back into the next decision.

The guiding value: "survives" beats "looks profitable." Discipline is never waived; aggression is a dial on top of it.

02Design principles

  1. Human-in-the-loop by default. Approval gating is the safety model; Auto is opt-in.
  2. Deterministic risk, independent of the model. The stop-loss watcher and circuit breaker are plain code with hard thresholds the LLM can't argue past.
  3. Quality over quantity. Most cycles are NO_ACTION; a daily cap and a minimum-conviction floor discourage overtrading and coin-flips.
  4. Every call is explainable. Reasoning, a bear case, cited sources, a confidence number, plus generated reports.
  5. Memory and learning. A per-stock stance book + a track record + calibration close the loop.
  6. Token-frugal. A compact digest; the default agent runs on a Claude subscription, not per-token billing.

The feedback arrow is the point: resolved outcomes re-enter the agent's context, so the loop tightens over time. The stance book also updates "sideways" every cycle — even on a NO_ACTION sweep the agent revises its per-stock plan, so memory changes far more often than it trades.

04Architecture, layer by layer

4.1 Data layer — the sweep

apis/briefing.mjs → fullBriefing() runs ~39 sources in parallel (30s timeout each, isolated failures). dashboard/inject.mjs → synthesize() maps raw payloads into one clean schema; lib/delta gates expensive LLM work when nothing material changed.

4.2 Intelligence layer

Ideas (lib/llm/ideas.mjs), theses (lib/llm/thesis.mjs, forward-pacing megatrend → "unpriced rung"), and the digest (compactSweepForLLM()) — the biggest token lever.

4.3 The agent — one call

lib/llm/analyst.mjs → generateProposal(): one call to Claude (CLI default; Gemini fallback), no tool loop, one JSON object out. Horizons double as risk bands: INTRADAY ~-2%, SWING ~-5%, LONG ~-12%.

4.4 Memory & learning

Stance book (lib/stances/store.mjs), track record / calibration (lib/llm/trackRecord.mjs, calibration.mjs), directives. See §10.

4.5 Risk layer — deterministic

Stop-loss watcher, circuit breaker, post-stop moratorium, mechanical guards. See §9.

4.6 Execution & lifecycle

lib/proposals/store.mjs + server.mjs → acceptProposal. See §6.

4.7 Delivery & control

Dashboard, Telegram, Propose/Ask. See §5.

4.8 State (runs/)

Flat JSON: settings, stances, decisions (ledger + P&L), proposals, directives, breaker, theses, moratoriums, ma-state, latest.

05Agentic flows — how the agent decides

Three distinct LLM flows. All are read-mostly except the sweep, the only one that can propose a trade.

5.1 The sweep decision loop (the main agent)

(digest +        (reasoning +     1. URGENT MAINTENANCE on a held name       (proposal
 MARKET_SETUPS +  strongest        (thesis broken / stop breached / MA        + stanceUpdates[])

  • THINK FIRST — reasoning + the single strongest bearCase before a verdict; if the bear case wins → NO_ACTION.
  • One proposal max — NEW_BUY, MAINTENANCE (usually a sell), or NO_ACTION.
  • Stance updates every sweep — even on NO_ACTION the agent revises its per-stock plan, so memory changes far more often than it trades.
  • Strategy mode tunes the bar for acting (Conservative/Balanced/Aggressive/Scalper/custom + regime-aware AUTO), never the risk floors.

5.2 Ask — read-only

Answers questions grounded in the live plan: holdings (real P&L), stances, active hard stops, recent trades, track record, directives, and the current sweep. It explains; it never changes state. In the news channel, /ask answers current-events/geopolitics grounded in the sweep (and can reply to a posted story).

5.3 Propose — user-driven plan edits

The user suggests a change in plain English ("watch URA", "promote MANE to swing", "drop WDC"). The agent returns ACCEPT / PARTIAL / DENY with reasoning, then applies accepted stance edits, a standing directive, or a horizon retype of a held position. Reckless ideas are denied.

06Position lifecycle — discovery to exit

DISCOVER ─▶ AGENT JUDGES ─▶ GATES ─▶ EXECUTE ─▶ HOLD / MONITOR ─▶ EXIT ─▶ RECORD
(board      (THINK + bear   (§9)     (place +    (per-sweep        (4 ways   (report +
 surfaces    case; pick a             log +       intel + stance    below)    learn;
 it)         real setup)              stance +    revise + retype)            stop → moratorium)
                                      enforced stop)

Entry. A candidate clears the board (§7), the agent judges it a real setup, it passes every gate (§9), and executes. On fill: the stance becomes HOLD with the real entry, the position's horizon, and a code-enforced hard stop.

Hold / monitor. Every sweep the position is re-read with company depth (§8). The stance is revised as the view changes, and the agent (or you, via /propose) can retype it up the horizon ladder (INTRADAY→SWING→LONG) when a winner has room — widening the stop and changing EOD behavior. The anti-churn guard stops a just-entered loser from being whipsawed out (winners still scalp fast).

Exit — four ways, each writes a report and closes the stance:

ExitTrigger & notes
Agent MAINTENANCE sellthesis break / take-profit the agent proposes; a full exit uses ClosePosition (exact qty, no dust)
Hard stopprice ≤ the enforced stop; auto-sells, no approval; a loss → moratorium (cooldown + logged failure)
Trailing stopa profit retraces past the trail distance; locks gains once in profit
EOD profit-lockan INTRADAY position up at the close; banks the gain before overnight risk

Intraday EOD sub-lifecycle. A late-session INTRADAY entry is blocked (INTRADAY_ENTRY_CUTOFF — no same-day runway). At the close: an INTRADAY winner profit-locks; a loser holds overnight (converts to SWING coverage) — "close when up, hold when down."

07Discovery & the MARKET_SETUPS board

lib/discovery/discover.mjs finds new names to buy. Every source already names tickers — the board harvests them, scores each, enriches the leaders, and ranks a shortlist the agent hunts from first.

Scoring — catalyst up, red flags down:

Then drop anything below DISCOVERY_MIN_SCORE (noise like a lone +3% wiggle). What reaches the agent is a ranked line with the catalyst, chart, and any ⚠ flags — e.g. MARKET_SETUPS: CEG (score 10 STRONG): insider-buy, bullish-sweep, thesis:AI | >MAs, RSI 61, RS +5 | news: …. The agent favors high score + a STRONG/BUILDING setup + no ⚠ flags, and is told that if the best option is a flagged support-test, that's a NO_ACTION, not a least-bad buy.

Limit: it's catalyst-and-price triggered — a name only appears if a signal named it or it moved enough to rank in movers. A quiet-but-good setup won't surface (no market-wide technical screener yet).

Each sweep, every name you hold, have a stance on, or that ranks as a discovery candidate is pulled individually — not just as a macro headline:

This is what lets the agent catch a thesis-break on a name you own (a court ruling, insiders dumping, a moving-average breakdown) instead of staying bullish on a stale thesis.

09Entry & risk guards

Entry gates — a NEW_BUY must clear all of these before it's placed (exits/maintenance are never gated):

Buying-power floora buy that would drop below the minminBuyingPower
No-size / price-safety / PDTno size, an implausible price, or a PDT violationmechanical

Deterministic risk layer (model cannot override):

  • Hard stop-loss watcher — auto-sells at the enforced stop, trails to lock gains, runs the intraday EOD lifecycle.
  • Circuit breaker — halts new buys at maxDailyLossPct / maxDrawdownPct (maintenance/exits still allowed).
  • Anti-whipsaw — MA-cross hysteresis + an anti-churn hold guard.
  • Post-stop moratorium — cooldown + logged failed thesis after a hard stop.

10How it learns (the loop that matters)

  1. A proposal is accepted → logDecisions records it with the stated confidence.
  2. positionResolver later marks it resolved (win/loss/breakeven + P&L).
  3. On the next sweep, buildTrackRecord() + buildCalibration() inject compact self-corrections.
  4. The agent adjusts: downweights losing horizons/signals, leans into winners, recalibrates confidence.

The single biggest lever on decision quality. It activates only after a minimum sample (TRACK_RECORD_MIN, CALIBRATION_MIN) so it doesn't over-fit two trades.

11Strengths

  • Safety-first by construction — approval gating + a risk layer the model can't override.
  • Analyst-grade breadth — macro + policy + congressional + SEC + semiconductor + OSINT in one view.
  • A real discovery funnel — ranked, vetted candidates with entry guards that filter noise and knife-catches.
  • It explains itself — reasoning, a bear case, cited sources, a confidence number, and reports.
  • It calibrates — Brier-scored confidence attacks overconfidence and cutting winners short.
  • Consistency via memory, cost-efficient, and tunable aggression without tunable risk.

12Weaknesses & limitations

  • Signal fragility on free tiers — keyed sources go dark on quota; the agent isn't yet told which are dark.
  • Latency vs. autonomous bots — approvals at sweep interval; every exit except the hard stop is a proposal.
  • Cold-start + live-only learning — no backtest/paper harness.
  • LLM variance — guards catch mechanically unsafe orders, not a plausible-looking bad idea.
  • Discovery is catalyst/price-triggered — a quiet-but-good setup won't surface.
  • Attribution per-confidence, not yet per-source; single-tenant flat-file state; market-hours bound.

14Where it's headed

Near-term: multitenancy — one shared data server runs the sweep + ideas/thesis LLM and writes to a database; many RedLine instances read from it and add per-user state. Market/OSINT keys are global; only SnapTrade user credentials and Telegram chat IDs are per-tenant.

Other extensions: per-source predictive scoring, a paper/backtest harness, a data-health line in the agent context, a news-first catalyst detector (catch a guidance/earnings surprise before the big move), and a confidence-decay exit (trim a held position once the agent's own confidence collapses).

15Worked example — how a new name is discovered (ORCL +12%)

A name you don't hold enters the system only through the movers screener — then travels to the agent:

  1. Front door — movers. apis/sources/movers.mjs (Yahoo gainers) ranks ORCL at +12% → synthesized.movers.gainers.
  2. Scored. harvestAndScore() scores the gainer by magnitude — ≥10% → 3 (a +3% wiggle is 1 and filtered as noise; this is how a catalyst mover clears the board but RIG-style churn doesn't).
  3. Monitored. ORCL joins the enrichment set as a top candidate and a big mover (≥6%).
  4. Enriched — the "why". POSITION_NEWS pulls "Oracle surges on FY2029 $30B free-cash-flow guidance"; POSITION_TECHNICALS shows it above both MAs, strong RS.
  5. Board. annotateBoard() → score 3 + setup + news ≈ 4 ≥ DISCOVERY_MIN_SCORE → on MARKET_SETUPS.
  6. Agent sees it. buildAnalystContext leads the NEW_BUY hunt from the board; ORCL is in front of the agent with its catalyst + chart, to judge re-rating vs. chase.
  7. If it buys → gates (§9) → execute → stance HOLD + horizon → hard stop → trade report.

The boundary: this is price-move triggered — ORCL's news is pulled because the move was big enough to rank in movers. A news-first "guidance/earnings-surprise" signal is the next upgrade to catch catalysts before the big move.
